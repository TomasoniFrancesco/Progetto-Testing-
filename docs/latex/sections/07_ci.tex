\section{Continuous Integration}
\label{sec:ci}

La continuous integration gira su GitHub Actions. Il senso è che a ogni push o
pull request i test partono da soli, così se rompo qualcosa me ne accorgo subito invece
che due settimane dopo.

Tutto sta nel file \texttt{.github/workflows/ci.yml}: fa la build Maven completa, lascia
fuori i test taggati \texttt{ui} (che hanno bisogno di Chrome e dell'app avviata, e sul
runner non ci sono) e alla fine salva il report JaCoCo come artifact scaricabile.

\begin{lstlisting}[language=bash, caption={.github/workflows/ci.yml (estratto)}]
on:
  push:
  pull_request:

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '17'
      - run: mvn -B -f java/pom.xml verify
      - uses: actions/upload-artifact@v4
        with:
          name: jacoco-report
          path: java/target/site/jacoco/
\end{lstlisting}

\screenshot{ci_success}{Esecuzione CI riuscita sul branch \texttt{main}}{%
Run della pipeline completato con successo: build Maven e test del package core tutti
verdi.}

Questo è il run verde su \texttt{main}.

Solo che avere la pipeline verde, di per sé, dimostra poco: dimostra che i test passano,
non che la CI se ne accorgerebbe se smettessero di passare. Per essere sicuro che il
meccanismo funzionasse ho quindi rotto il codice apposta. Su un branch a parte, chiamato
\texttt{ci\_failure} e lasciato sul repository come prova, \texttt{assegnaPosto} è stato
modificato per restituire sempre \texttt{TipoPosto.NESSUNO}. Al push la
pipeline è andata in rosso, con i test di \texttt{ParcheggioTest} e
\texttt{SmartParkingFSMTest} falliti sugli assert dell'assegnazione. Il branch
\texttt{main} è rimasto com'era.

\screenshot{ci_failure}{Esecuzione CI fallita sul branch \texttt{ci\_failure} (regressione introdotta di proposito)}{%
Run fallito dopo aver forzato assegnaPosto a restituire sempre NESSUNO: la CI intercetta
la regressione e blocca la build.}

Quello che mi porto a casa da questa parte è che il valore della CI non è tanto far
girare i test, che posso farlo anche in locale, quanto non potermene dimenticare: ogni
commit resta legato a una prova che in quel momento il codice funzionava.
